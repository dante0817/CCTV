CCTV MONITOR P0.12 — COMPLETE FRESH-INSTALL PACKAGE

This is a complete P0.12 application source package. It includes:
  - P0.11 USB + generic RTSP/Tenda-ready camera architecture
  - P0.11.1 runtime truth, recovery, dashboard, storage and diagnostics
  - P0.11.1a Node 24 TypeScript compatibility fixes
  - P0.11.2 persistent Operational Events
  - P0.12 persistent/revocable sessions and hardened Audit
  - Admin/Viewer role access and per-camera Viewer ACLs
  - per-user AI grant control
  - MediaMTX configuration/setup and Windows startup/qualification scripts

P0.12 SECURITY HIGHLIGHTS
========================
  - Browser sessions persist in SQLite across server restart.
  - Only SHA-256 session-token hashes are stored in SQLite.
  - Users can revoke individual sessions / sign out other sessions.
  - Admin can revoke sessions for managed users.
  - New/changed passwords require at least 12 characters.
  - Existing password hashes remain accepted for upgrade compatibility.
  - User disable/password/security changes invalidate affected sessions/tokens.
  - Media authorization revalidates active user, session and camera ACL.
  - New Viewer accounts default to AI disabled; Admin can grant AI per user.
  - Audit details redact passwords, tokens, cookies, authorization data,
    RTSP credentials, API keys and related secrets before persistence.

NOT BUNDLED BECAUSE THEY ARE MACHINE/RUNTIME DEPENDENCIES
=========================================================
  - Node.js/npm

FRESH INSTALL
=============
1. Extract this package into a NEW writable folder, for example:
     X:\2M\000\my Projects2\CCTV\cctv-monitor-p0.12-complete

2. Install Node.js 22.5+ (Node 24.x is supported).

3. Install FFmpeg and either put ffmpeg.exe in PATH or set FFMPEG_PATH in .env.

4. Recommended first run from PowerShell:
     .\FIRST-RUN-P0.12.cmd

   It will:
     - create .env from .env.example when missing
     - create data\ when missing
     - install npm dependencies
     - use npm ci if package-lock.json exists
     - run TypeScript check
     - run the full regression suite
     - run the production build
     - run setup preflight / MediaMTX setup
     - start CCTV Monitor

5. Browser address:
     http://localhost:3000

   Do not browse to http://0.0.0.0:3000.

6. After software verification, run:
     .\QUALIFY-P0.12.cmd

UPGRADING / REUSING EXISTING PERSISTENT DATA
============================================
For a fresh P0.12 folder, you may copy from the prior verified installation:
     .env
     data\
     data\.credential-key   (if present)
     package-lock.json      (only when it matches the same dependency set)

Do NOT copy old node_modules; install dependencies fresh.
Back up data\ before first P0.12 launch. Schema migration is automatic.

P0.12 QUALIFICATION TARGET
==========================
Verify:
  - existing USB/WebRTC live view still works
  - Operational Events from P0.11.2 still persist
  - two browsers can sign into the same user
  - My Sessions shows both sessions
  - revoking one session logs that browser out without killing the other
  - a surviving session remains valid after server restart
  - password change invalidates other sessions
  - disabling a Viewer blocks subsequent API/media authorization
  - removing camera ACL blocks new camera/media authorization
  - new Viewer defaults to AI disabled
  - Admin can explicitly grant AI access
  - Audit records security/session/user changes
  - no password/token/cookie/credential secrets appear in Audit
  - Ctrl+C shuts down cleanly

SECURITY NOTE
=============
Revoking a session blocks future API and MediaMTX authorization. An already-
established WebRTC peer connection can remain alive until it disconnects; P0.12
does not forcibly terminate an existing MediaMTX peer connection.

DO NOT run `npm audit fix --force` as part of first-run qualification. Review the
actual `npm audit` report first; forced major dependency upgrades can break the
known-good CCTV media/runtime baseline.

Recording/NVR remains deferred to P0.13.
